# WHMCS EPay Secure

WHMCS EPay Secure 是一款适用于 WHMCS 的 EPay兼容支付网关插件。

本插件用于在 WHMCS 中接入兼容 EPay API 的支付服务商，支持多种订单方式，并解决了部分epay兼容系统订单过期问题

当前版本：**v2.2**

> 本项目为第三方开源插件，与 WHMCS、EPay 或任何支付服务商均无官方关联。

---

## 功能简介

使用本插件后，WHMCS 客户可以直接从发票页面发起付款。

适用于：

- WHMCS 新订单付款
- WHMCS 续费发票付款
- 支持 EPay兼容接口的支付服务商
- 支付宝、微信等由支付服务商提供的支付方式（注： 具体字段请联系你的支付提供商）
- whmcs 多币种自动转换
- 从其他 EPay 插件迁移到新版插件（注意： 部分其他插件可能采用了会导致冲突的实现，建议安装前备份数据库）

完成安装后，只需在 WHMCS 后台填写支付服务商提供的商户 ID、商户密钥和网关地址即可使用。

---

# 安装前准备

请准备：

1. 一套已经正常运行的 WHMCS。
2. 一个兼容 EPay / 易支付 API 的支付服务商账户。
3. 支付服务商提供的商户 ID（PID）、商户密钥（KEY）和支付网关地址。
4. WHMCS 网站文件和数据库的管理权限。

正式安装或升级前，请先备份：

- WHMCS 数据库
- 现有 EPay 插件文件
- WHMCS 相关配置

---

# 新安装

## 1. 上传插件文件

解压发布包，将其中的：

```text
modules/
```

目录上传到 WHMCS 根目录。

例如 WHMCS 安装目录为：

```text
/home/wwwroot/whmcs/
```

上传后应能看到：

```text
/home/wwwroot/whmcs/modules/gateways/epay.php
```

生产环境只需要上传 `modules/` 目录。

以下内容不需要上传到网站目录：

```text
README.md
*.sql
*.sha256
```

---

## 2. 初始化数据库

> 如果你不懂这是在干什么，那就别鸡巴限制数据库权限，权限正常的情况下插件会自动配置数据库

正常情况下插件会自动创建所需的数据库表，但是部分用户可能因为缺少CREATE TABLE 和 ALTER TABLE 权限导致无法自动配置数据库，你可以使用本仓库下的 install.sql 来手动配置

其余俩sql文件请勿在生产环境执行，此为开发者本地测试时使用的
---

## 3. 启用支付网关

登录 WHMCS 管理后台，进入支付网关设置页面，找到：

```text
EPay Secure
```

并启用。

然后填写支付服务商提供的信息。

建议配置：

| 配置项 | 建议 |
|---|---|
| 商户 ID | 支付服务商提供的 PID |
| 商户密钥 | 支付服务商提供的 KEY |
| 支付网关地址 | 例如 `https://pay.example.com`，不需要带submit.php之类的 |
| 支付方式 | 例如 `alipay` 或 `wxpay`（具体字段请联系你的支付提供商，某些支付可能是 zfb wxzf 之类的字段） |
| 下单方式 | 如果你不知道这是什么，那就选择 `submit.php` |
| 支付订单有效期 | 联系你的支付提供商 |
| MAPI 支付入口缓存时间 | 默认 `5` 分钟 |
| 手续费率 | 仅为whmcs后台收入计算使用，和用户支付金额无关 |
| 回调后二次查询订单 | 你不知道这是干什么的就别开 |
| 允许 HTTP | 建议关闭 |
| 关闭 TLS 证书校验 | 建议关闭 |

支付网关地址只填写站点地址，例如：

```text
https://pay.example.com
```

不要填写：

```text
https://pay.example.com/submit.php
```

或：

```text
https://pay.example.com/mapi.php
```

保存设置即可。

# 从旧版插件升级

如果你之前已经使用旧版此插件或其他epay插件，请不要先在 WHMCS 后台删除支付网关。

v2.2 仍然使用相同的支付网关模块名称，可以直接原位升级。

## 1. 备份

升级前请完整备份 WHMCS 数据库以及配置文件。

## 2. 覆盖文件

将 v2.2 发布包中的：

```text
modules/
```

覆盖到 WHMCS 根目录。

不要删除 WHMCS 后台原有的 EPay 支付网关配置。

## 3. 选择正确的升级 SQL

> 同上，插件会自动配置数据库，除非你需要手动配置，否则不要执行sql文件

## 4. 检查支付设置

升级完成后进入 WHMCS 支付网关设置，确认以下内容仍然正确：

- 商户 ID
- 商户密钥
- 网关地址
- 支付方式
- 下单方式

然后重新保存一次设置。

# 安装后的测试

正式开放给客户使用前，建议完成以下测试。

使用小额金额完成一次真实付款。

付款后确认：

- 支付平台显示付款成功
- WHMCS 发票变为 `Paid`
- WHMCS 中存在对应交易记录
- 客户不会被要求再次付款

## 多币种测试

本插件支持多币种转换，如果你的 WHMCS 使用多个币种，并开启了 `Convert To For Processing`，建议额外测试一张不同币种的发票。

例如：

```text
发票：USD
支付网关：CNY
```

付款完成后，应确认 WHMCS 发票中的入账金额正确。

# 关于旧订单

从其他 EPay 插件升级后，升级前已经创建的旧支付订单可能仍然存在一段时间。

v2.2 会为这些旧订单保留一个临时兼容回调。

如果旧订单在升级后才完成付款，插件可能会将该付款标记为：

```text
paid_review
```

这表示支付平台已经确认收到付款，但是由于你此前安装的插件可能有某些特殊行为，所以本插件不会进行入账操作

此时客户将不能再次通过该发票重复付款。

---

# 关于 `paid_review`

如果某笔付款显示为：

```text
paid_review
```

请不要直接重新开放付款，这是本插件做的防御性编程。

正确处理流程：

1. 登录支付服务商后台。
2. 确认该笔交易确实已经到账。
3. 核对订单号、交易号和实际付款金额。
4. 在 WHMCS 后台为对应发票正确记录付款。
5. 确认账务无误后，再手动确认账单。

`paid_review` 的目的，是防止支付平台已经收到第一笔款项，但 WHMCS 尚未完成入账时客户再次支付。

# 常见问题

## 可以同时安装旧版和新版吗？

不建议。

v2.2 是旧版 EPay 插件的升级版本，应直接覆盖升级，而不是作为第二个独立 EPay 网关同时运行。

## `tests` 文件夹需要上传吗？

不需要。

`tests` 仅用于开发和发布前自检，生产环境不需要部署。

## SQL 文件需要上传到网站吗？

不需要。

SQL 文件只用于数据库初始化或版本升级。执行完成后可以保存在本地，不需要放在 WHMCS 网站目录。

## 一定要开启“回调后二次查询订单”吗？

该功能属于额外的安全确认机制。只有在确认支付服务商兼容对应订单查询接口后才建议开启，同时如果你搞不明白这是干什么的，请保持关闭

## 商户密钥泄漏了会怎么样

epay订单的安全性完全建立在密码学之上，任何获取了你的支付密钥的人都可以伪造订单已付款
